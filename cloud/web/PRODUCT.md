# Product

## Register

product

## Users

Pod Cloud 控制台的两类使用者，同一屏上并存：

- **管理员**：出海 OPC / 独立开发者本人，或 2–10 人微型工作室的技术负责人。刚跑完 `pod record` / `pod sync`，回到控制台核对"这台机器上的 agent 到底被允许碰什么"。他会改策略——这是控制台里少数几个会真正改变运行时行为的动作。
- **只读成员**：租户里的其他成员，以及被拉进会议看结果的客户。不配置策略，只回答两个问题：**我的 agent 被允许做什么、谁改的、什么时候改的**。没有培训、没有文档，打开就要看懂。

**使用情境**：工作日白天，浏览器窗口开在编辑器旁边。翻查（"为什么这个调用被拒了"）、核对（"这条策略到底放行了什么"）、投屏（给客户证明数据没离开本机、每个判断都有出处）。

**要完成的任务**：30 秒内回答三个问题——**哪些 agent 受这条策略约束 → 它放行了什么、挡住了什么 → 这份策略最近被谁改过**。

## Product Purpose

Pod Cloud Web 是 pod 的云端控制平面：把本机 agent 上报的策略、审计哈希链、调用链聚合成一屏可读、可核查的资产视图。

策略中心是其中唯一一处"未来行为的定义"——它不描述已经发生了什么，而是规定接下来允许发生什么。因此它的成功标准不是"信息全"，而是**改之前看得懂后果、改之后追得回原因**。

## Brand Personality

**克制、可信、可核查**（restrained, credible, verifiable）。

安全工具的自信来自把证据摆出来，不来自形容词。语气像一份被认真维护的台账：安静、精确、不恐吓、不营销腔。术语保留英文原文（agent / server / tool / policy / deny / approve）。

## Anti-references

- **恐吓式安全仪表盘**：满屏红色、"RISK SCORE 87" 大字、没有出处的结论。
- **通用 SaaS 后台模板**：KPI 大数字 + 渐变强调 + 堆叠卡片阴影。
- **终端崇拜**：为了"极客感"牺牲可读性——通篇等宽字体、荧光绿文字、纯黑背景。
- **只读观众被当空气**：界面默认"你会编辑"，只读成员看到的是一排点不动的按钮和看不懂的 JSON。
- **夸张叙事**：与 `packages/gateway/src/snapshot.ts` 头注释确立的工程纪律一致——"说清楚不夸大"。

## Design Principles

1. **证据优先，结论其次**：每个判断都能点回出处（策略行 / 审计条目 / 调用链 path）。不出现无来源的结论。
2. **说清楚不夸大**：缺数据就写"未记录"，不用模糊的"安全 / 风险"标签掩盖信息缺口；宁可显示空状态也不编造。
3. **只读是默认，写操作要显式**：查看不改变任何状态；一切会改变运行时行为的动作（应用模板、回滚、删除）都必须说明后果。
4. **只读观众是一等公民**：同一页面按角色降级为只读视图，而不是隐藏入口或留下死按钮。只读状态要自我解释，不需要培训。
5. **本地优先的信任观感**：界面本身要让用户确信数据没有离开本机——只读默认、来源可见。

## Accessibility & Inclusion

- WCAG 2.1 AA：正文对比度 ≥ 4.5:1，非文本元素 ≥ 3:1。
- **状态不能只靠颜色区分**：三态决策（allow / approve / deny）、diff 增删、连接健康度都必须同时有文字或符号标记。
- 支持 `prefers-reduced-motion`。
- 界面语言中文为主，技术术语保留英文原文。
- 键盘可达：所有可交互元素有可见 focus 态。
- 双主题（暗色优先 + 亮色）：一切颜色走 `--fh-*` token，不写死 hex，否则另一个主题的对比度会失效。
