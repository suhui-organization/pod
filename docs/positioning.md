# pod 定位（路线 A）：MCP 最小权限编译器

> 状态：2026-09-09 定稿。本文是 pod 对外叙事与取舍的唯一锚点；与本文冲突的旧文案一律以本文为准。

## 1. 一句话

**pod 从 AI agent 的真实行为里编译最小权限策略。**

英文：**pod compiles a least-privilege policy from what your agent actually did.**

不是"又一个 MCP 网关"，不是"又一个安全扫描器"，而是两者之间缺失的那一步：**把观测到的行为，变成可执行、可验证的最小权限规则。**

## 2. 目标客户（ICP）

| 优先级 | 客户 | 为什么现在需要 |
| --- | --- | --- |
| P0 | 2-10 人的微型工作室 / AI 代理公司 | 同时用多个 agent 和十几个 MCP server；要给客户交代"agent 能碰什么、做过什么"；没有专职安全 |
| P1 | 出海独立开发者 / OPC | 有 GDPR / 数据出境焦虑；愿意为"省心 + 可证明"付费，但个人订阅意愿弱 |
| P2 | 安全敏感的中型团队 | 已有 gateway/sandbox，但策略靠手写、审计靠拼；需要"策略编译器 + 证据"补齐 |

**不服务**：需要托管 MSSP、渗透测试、等保合规全套的企业（v1 明确不做）。

## 3. 问题

Agent 的工具权限默认是"全有或全无"：

- 平台原生沙箱（Claude Code / Codex / Gemini CLI）只保护**自己那一个 agent**；
- MCP 网关（agentgateway / ToolHive / ContextForge / Docker）给了你**执行点**，但策略要你手写；
- 扫描器（Snyk Agent Scan / mcp-guard）告诉你**暴露面**，但不告诉你**该允许什么**；
- 结果：用户要么全放开（裸奔），要么写一份过宽/过严的策略然后放弃维护。

## 4. 解决方案：四步闭环

```text
1. record    pod record / pod onboard --yes      只录不拦，采集真实工具调用
2. compile   pod policy draft --diff <baseline>  从语料生成最小权限策略 + 变化清单
3. enforce   pod serve --policy <draft>          deny > approve > allow，fail-closed
4. prove     pod verify-audit / export-evidence  SHA-256 哈希链 + 可验证证据包
```

**唯一不可替代的资产是第 2 步的语料。** 用得越久，策略越贴合真实行为；这是竞品无法直接复制的数据飞轮。

## 5. 差异化（诚实版）

| 能力 | pod | Vigils（最接近的竞品） | MCP 网关（agentgateway/ToolHive…） | 平台原生沙箱 |
| --- | --- | --- | --- | --- |
| 从真实行为编译策略 | ✅ **核心** | ❌（有 descriptor drift，不生成策略） | ❌（手写策略） | ❌ |
| 策略 diff（收紧/放宽清单） | ✅ | ❌ | 部分 | ❌ |
| 跨 agent 统一审计 | ✅ | ✅（8 个 agent 一键接管） | 部分 | ❌（只管自己） |
| 沙箱 / 隔离强度 | ❌（进程内转发） | ✅（Landlock/Wasmtime） | ✅（容器/进程） | ✅ |
| 密钥不进模型 | ⚠️（输出侧正则+熵） | ✅（Keychain + 短期租约） | 部分 | 部分 |
| 桌面 UI / 一键安装 | ❌（CLI） | ✅（Tauri + Chrome 扩展） | 部分 | ✅ |
| 证据包导出/验证 | ✅ | ⚠️（FTS5 搜索，非证据包） | 部分 | ❌ |
| 社区与分发 | ❌（Gitee 0★） | ✅（303★，双语） | ✅（数千★） | ✅（默认内置） |

**结论**：不要在"沙箱强度 / 实时脱敏 / 桌面体验"上正面竞争——那是 Vigils 和大厂的主场。pod 赢在**策略生成 + 证据**这两个环节。

## 6. 商业模式与定价（替换旧的 $9-19 个人档）

| 层级 | 内容 | 定价 |
| --- | --- | --- |
| 开源核心 | 网关、策略引擎、审批、哈希链审计、`policy draft`、`scan`、证据包 | **$0**（Apache-2.0） |
| Team（主推） | 跨机器/跨 agent 聚合、策略模板库、共享审批、合规报告导出 | **$49-199/月**（按席位/机器） |
| 审计服务（先验证） | 一次性"agent 权限审计"：扫 + 录 + 编译策略 + 证据报告 | **$500-5,000/次** |

**不再做** $9-19 个人订阅：Vigils 等同类开源项目已把这一档压到零，个人付费意愿未被任何公开数据验证。付费方是**为交付负责的老板**，不是个人开发者。

## 7. 90 天验证指标

| 指标 | 目标 | 为什么 |
| --- | --- | --- |
| 编译出的策略数 | ≥ 50 | 证明 `policy draft` 是真实需求，不是 demo |
| 策略被实际启用（`pod serve`） | ≥ 10 | 证明"编译→执法"闭环有人走完 |
| 证据包导出 | ≥ 20 | 证明"可证明"是付费点 |
| 付费信号（Team 或审计服务） | ≥ 3 个明确报价区间 | 验证生死问题 |
| GitHub star | ≥ 200 | 分发最低门槛 |

## 8. 不做什么（防止叙事再次发散）

- 不宣传"通用 AI Agent 安全平台"；
- 不承诺沙箱/隔离能力（不是我们的强项）；
- 不把 Pod Cloud 当作核心卖点（本地核心必须完整可用）；
- 不在 README 同时讲 10 个功能——`policy draft` 是唯一 hero，其余是支撑。
