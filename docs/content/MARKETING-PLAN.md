## 2. 渠道取舍

**放弃小红书**：读者是消费/生活向，技术内容要么被限流、要么找不到人；正文链接不生效，等于把唯一能验证转化的入口砍掉。投入产出比不成立。

**国内只留 CSDN**：中文技术内容还有搜索长尾的地方不多，CSDN 的百度收录是实打实的。**只做"发布"**——不运营评论区、不追热点，把它当"SEO 着陆页"而不是社区。

**海外这是主场**：这个项目的读者（AI infra / 安全 / MCP 构建者）几乎全在英语技术社区，且这些平台**链接可点、读者会真的跑命令**。

**本环境实测的硬约束**（决定了谁现在能做、谁做不了）：

| 平台 | 可达 | 登录 | 说明 |
|---|---|---|---|
| X | ✅ | ✅ 已登录 | 主力渠道 |
| LinkedIn | ✅（慢） | ❌ | 有 Google 一键登录入口 |
| Hacker News | ✅ | ❌ | 提交需要账号 |
| dev.to | ✅ | ❌ | 需要账号 |
| Bluesky | ✅ | ❌ | 需要账号 |
| Reddit | ❌ | — | **整站被网络层拦截**（"blocked by network security"），本机无法操作 |

## 3. 各渠道的规则与打法

**X（主力）**

| 规则 | 含义 |
|---|---|
| 外链压触达 | 链接放**第一条回复**，主帖只留结论 + 图 |
| 首小时看互动速度 | 回复权重最高；0 回复的帖基本判死 |
| 粉丝数 = 初始投递池 | 冷启动唯一有效动作：去别人帖下留**带数据的实质回复**，每天 5 条 |
| 长内容用线程 | 一篇稿拆 4–6 条，每条能独立成立 |

**Hacker News（一次性高杠杆）**

- 形态是 `Show HN: <一句话说清是什么>`，**标题决定一切**，正文只讲"为什么做、怎么做、现在什么状态、边界在哪"。
- 社区极度反感营销腔和夸大，**第一句就要承认它做不到什么**（我们有现成的：不是沙箱、看不到 agent 之间的对话、防不住整机被攻破）。
- 发帖时机：美东工作日上午（北京 21:00–23:00 或次日 09:00）。发出后**头两小时必须守在评论区**逐条回。
- 一次只发一次；重发会被标记。

**LinkedIn（触达甲方与同行）**

- 机制是人际网络扩散：**评论别人的帖子**带来的曝光通常高于自己发帖。
- 内容形态不同：不要贴 terminal 截图当主角，要讲**风险与合规的语言**（"agent 有哪些权限、谁能证明它没越权"）。
- 适合发：项目里程碑、一次真实事件的复盘、"我们为什么开源"。

**dev.to（长尾 SEO）**

- 适合把 `02-quickstart` 与 `03-owasp-101` 改写成英文教程；**canonical link 指向自己站点**，避免重复内容分权。
- 有 `#security` `#ai` `#opensource` 这类标签体系，比 X 的 hashtag 有用。

**Bluesky / Mastodon(infosec.exchange)**

- 安全圈在 Mastodon 的 infosec.exchange 上很活跃，适合发布"短结论 + 链接"（这两个平台**链接不降权**，和 X 相反）。
- 不追求爆款，追求**被安全从业者转发**；发帖语气要比 X 更克制（那边反感增长话术）。

**CSDN（国内唯一保留）**

- 把中文四篇稿重新排版发出去：代码块、目录、封面图齐全，标题含搜索词（`AI Agent 权限`、`MCP`、`最小权限`）。
- 正文可以放仓库链接（国内平台对 gitee 链接更友好），但**主推 gitee 镜像**——读者在国内拉 GitHub 常常失败。
- 不运营评论、不追热点，把它当"能被百度搜到的落地页"。

## 4. 第 0 步（先做，1 小时内）

**修漏斗**：官网 [podsec.vercel.app](https://podsec.vercel.app/) 的安装命令仍钉在 `v0.2.0`，仓库已经是 `v0.3.0`。海外的开发者**真的会照着官网敲命令**，装到旧版等于白导流。这与 [../PUBLISHING.md](../PUBLISHING.md) 里 A4"版本号一起改"是同一类问题。

## 6. 每周节奏（三时段，每时段一条）

| 时段（北京） | 海外 | 国内 |
|---|---|---|
| 09:00–10:00 | X：回复 5 条（美东晚间仍在线的欧美开发者） | CSDN：发第 1 篇 |
| 12:00–13:00 | LinkedIn：评论 3 条 + 每周 1 条自己的帖 | — |
| 21:00–23:00 | X：发 1 条主帖（美东上午）；每周挑一天改成线程 | CSDN：发第 2 篇（如果这周有两篇） |

**置顶与主页**：X 主页置顶最好的那条（现在置顶的是扫描帖，保持）；LinkedIn 的 headline 与 about 要把项目写清楚，那是被点进来的第一屏。

## 7. 指标与判据

| 指标 | 判据 |
|---|---|
| GitHub star | 唯一算数的转化指标 |
| 官网 → 安装命令的版本正确性 | 每次发版后必须核（现在是错的） |
| X：回复带来的主页访问 | 两周后仍接近 0 → **换话题**，不是加量 |
| HN：头两小时评论数 | 无评论 = 标题没抓住，下次换标题角度 |
| CSDN：单篇阅读量 | 低于 500 说明标题/关键词没对上，先改标题重发 |

## 8. 不做什么

- 不在 HN 上写营销话术（会被直接踩死，且贴主账号会掉 karma）
- 不在 X 正文放链接（放在首回复）
- 不用中文技术长文直接机翻发海外
- 不在 Reddit 上徒劳尝试（本机网络被拦，先解决可达性再说）

## 9. 维护

- **每周复核**第 1 节的账号数据；平台规则变动优先改第 3 节，并更新文首日期。
- 第 2 节的可达性表要重测：Reddit 的拦截可能是网络环境相关，换网络后可能可用。
