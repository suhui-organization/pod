# pod 能做什么、给你带来什么

> 面向第一次接触这个项目的人：这一页只讲**能力与价值**，不讲实现。
> 安装看 [README](../README.md)，云端部署看 [deploy-cloud.md](deploy-cloud.md)。

## 一句话

**pod 从 AI agent 的真实行为里编译出最小权限策略，并给每一次执行留下可验证的证据。**

不是又一个 MCP 网关（那些让你**手写**策略），也不是又一个扫描器（那些告诉你**暴露面**却不能告诉你该允许什么）。pod 补的是中间那一步：**把观察到的行为变成可执行、可验证的最小权限规则**。

## 四个动作，一条闭环

```
record   只录不拦，采集 agent 真实调用（几天就够）
   ↓
compile  从语料编译最小权限策略，并 diff 出"收紧了什么、放宽了什么"
   ↓
enforce  网关执法 deny > approve > allow，fail-closed
   ↓
prove    SHA-256 哈希链审计 + 可导出、可校验的证据包
```

每一步都能单独用，但真正的价值在闭环：**你不需要凭空写一份策略，也不用在出事之后靠回忆。**

## 能做什么（能力地图）

### 一、把行为变成策略

| 能力 | 命令 |
|---|---|
| 只录不拦地采集真实工具调用 | `pod record` / `pod serve --record-only` |
| 从语料编译最小权限策略（读→allow、写/执行→approve、破坏性→deny） | `pod policy draft` |
| 与基线策略 diff：收紧/放宽/移除各有哪些 | `pod policy draft --diff baseline.json` |
| 策略体检：空 deny、`allow: ["*"]`、fail-open 的 `defaultDecision` | `pod lint` |

**用多久，策略就多贴合。** 唯一的护城河是你的语料——用得越久，它越知道你的 agent 真正需要什么。

### 二、在工具边界上执法

| 能力 | 说明 |
|---|---|
| 三态决策 | `deny > approve > allow`，未登记的一律拒绝（fail-closed） |
| 能力级规则 | 不只看工具名，还看它实际具备的能力（读密钥/外联/执行/破坏性写…） |
| 人工审批闸门 | 高危调用挂起等人批，超时按拒绝处理；approver 与理由进审计 |
| 密钥防线 | 敏感路径拒绝读取 + 输出侧正则 + 高熵兜底（未知格式的密钥也拦得住） |
| 出网判定 | 参数里出现的主机按你的 allow/deny 列表判定（默认关，规则驱动） |
| 来源白名单 | 启动前校验 MCP server 的 command/包/版本，挡住供应链投毒 |

### 三、留证据（出事之后能说清楚）

| 能力 | 说明 |
|---|---|
| 不可篡改审计 | 每次调用进 SHA-256 哈希链，改一条整链对不上；敏感内容只存哈希 |
| 一键校验 | `pod verify-audit` 扫全链，指出第一处断裂 |
| 证据包 | `pod export-evidence` 导出可交付的证据包，`pod verify-evidence` 独立校验 |
| 时间线与周报 | `pod timeline` / `pod digest`：按 agent、工具、时间切片 |
| 快照与回滚 | 高危写操作前拍快照，`pod rollback` 恢复文件 |

### 四、守住控制平面（不是只盯工具调用）

工具调用只是数据平面。真正被忽略、也最容易被做手脚的是**运行环境本身**：

| 能力 | 命令 | 拦得住什么 |
|---|---|---|
| 生命周期钩子审计 | `pod posture` | 插件"更新"后把命令悄悄挂到会话事件上（HookPry 类攻击） |
| 配置冻结与漂移 | `pod posture freeze/verify` | 审批被关掉、网关地址被改、密钥引用换成明文 |
| 记忆完整性 | `pod posture` | 长期记忆被投毒，影响之后每一次决策 |
| 包来源固定 | `pod posture` | 同名 MCP server 被换成另一个包 |
| 每 agent 独立身份 | `pod identity` | 共享凭证导致"出事说不清是谁做的" |
| 委托链收窄 | `pod delegate` | 高权限 agent 把权限扩散给子 agent |
| JIT 令牌 | `pod grant` | 长期静态令牌一旦泄露就长期有效 |
| 熔断与溯源 | `pod quarantine` / `pod trace` | 被污染的 agent 继续扩散；事后找不到源头 |
| 信任传播异常 | `pod anomaly` | 平时不委托的 agent 突然密集签发委托 |
| 审计链自身健康 | `pod posture`（`auditHealth`） | 钩子静默停摆、链断裂导致"看起来在记、其实没记" |

### 五、跨 agent 的统一视图 + 可选云端

| 能力 | 说明 |
|---|---|
| 一个 agent 一份策略 | 策略绑定 agent 身份；多 agent 各管各的，不互相污染 |
| 覆盖率与漂移检查 | `pod coverage --strict`：还有哪些 MCP server 绕过网关（退出码可直接挂 CI） |
| 可选云端控制平面 | 自托管 Pod Cloud：注册 agent、汇聚审计、策略中心、告警、时间线、控制平面事件、合规报告 |

## 给你带来什么

| 你现在的处境 | pod 之后 |
|---|---|
| 不知道 agent 到底能碰什么，只能全放开或全关掉 | 从真实行为编译出一份**你会去维护**的策略 |
| 出事之后只能靠回忆："它昨晚到底干了什么？" | 5 分钟拿出**可验证**的时间线，还能证明没被改过 |
| 同时用好几个 agent，没人有全局视图 | 一个本地视图 + 可选云端，跨 agent 统一审计 |
| 想给客户/审计方交代，只能口头保证 | 证据包 + 校验命令，**对方自己就能验** |
| 担心策略写太严打断工作流 | 先 record 几天、审批可旁路、支持快照回滚 |
| 不知道哪些判定该多严 | **判定规则归你**：`~/.pod/rules.json` 改一行就换口径 |

## 亮点（与同类工具的差别）

1. **策略是编译出来的，不是手写的。** 网关给你执行点，扫描器给你暴露面，pod 给你规则本身。
2. **证据可独立验证。** 哈希链 + 证据包，验证不需要信任 pod 或它的运营者。
3. **判定规则由用户定义。** 阈值、正则、严重级别、可信来源全在 `~/.pod/rules.json`；代码只给默认值，规则写错会 fail-closed 报错而不是悄悄退回默认。
4. **本地优先。** 策略、审计、密钥不出你的机器；云端是可选控制平面，不是数据必经之路。
5. **审计的是控制平面，不只是工具调用。** 钩子、配置、记忆、身份、委托——这些才是"合法动作被滥用"的地方。
6. **坏消息会说出来。** 链断裂、长时间没有写入、agent 缺身份——都被显式报出来，而不是留一个永远平静的仪表盘。

## 诚实的能力边界

写清楚不做什么，比夸大能力更能建立信任：

- **不做沙箱隔离**：网关是进程内转发。需要强隔离时用平台原生沙箱或容器，pod 的策略与证据可以叠在上面。
- **不做协议本体**：不实现 A2A/mTLS/SPIFFE。跨组织 agent 通信不在覆盖范围；身份与委托用本地签名链等价覆盖。
- **不把行为漂移当主防线**：agent 行为随 prompt 版本漂移，统计基线误报率降不下来。pod 主防线是**可判定的规则**，异常检测只作辅助信号。
- **防不住本机被完全攻陷、agent 平台自身后门、LLM 提供商的泄露**：这些只能通过减少暴露面和分机器来缓解。
- **看不到 agent 之间的对话**：pod 只在工具边界与自身记录内可见，"推理级联"这类跨 agent 语义污染不在覆盖范围。

完整威胁模型与不防御清单见 [threat-model.md](threat-model.md)。
